# 第一条：失败绝不返回提示词

这是这一版最要紧的一条，而且它**在换引擎之前就已经在了**：

```python
except Exception as e:
    log.warning("chat 失败(%s)，降级返回原文截断", type(e).__name__)
    return truncate(prompt, 240)
```

也就是说模型挂了的时候，**"多头论点"是提示词的前 240 字**——
没有异常、日志一行 warning、报告照出，然后走完材料闸门、进论点台账、
被 CRO 定仓、推到你面前。

本地模型很少挂，所以这条一直没咬到人。**换成远程 API 之后，
失败模式从"服务没起"变成限流 / 529 / key 过期 / 超时 —— 每天都可能发生。**

改法不是一刀切：翻译、摘要、分类那三处**保留降级**（它们外面有
`_strip_echo` 认得出回声并退回原文，降级在那里是安全的）。
辩论和判定走 `strict=True`，**失败抛异常**。

上层已经会把异常记成 `FAILED` 并进心跳 —— 那是对的落点：
今天这只票没研究成，明天重来。

# 第二条：不许悄悄退回本地

三条路都会**停下来抛异常**，而不是退回 gpt-oss：

```
CIO_DEBATE_ENGINE 拼错一个字      → 抛（不认识的 provider）
没配 API key                     → 抛，并写明"不会自动退回本地"
调用失败 / 空回复                 → 抛
```

按你的选择（失败转 FAILED，明天重来），这是配套的：
**退回的话，论点台账里会同时存在两个引擎写的论点，而没人知道哪条是哪个。**

# 第三条：产出记得住是谁写的

`UnitAAdvice` 多了三格，论点台账多了一列：

```
engine          ollama:gpt-oss:20b  /  claude:claude-sonnet-5
engine_remote   这一轮的材料有没有离开本机
usage           {calls, input_tokens, output_tokens, usd, price_table_as_of}
```

你选的验证方式是"先换了再说，用复核台账评"。**那就更需要这一列**——
它让比较可以**回溯地**做出来：等台账攒够样本，可以按 engine 拆开看，
而不必事先跑 A/B。

> 顺带说一句实话：现在那个复核台账测的是**筛子**
> （"这条线索值不值得占用研究时间"），判断做在一部启动**之前**，
> 所以它评不了辩论质量。要评辩论，还缺一个**论点层的复核台账**
> （同一套 mark/stats 机械，标的是一部产出）。
> 我没有自作主张去建它 —— 但 `engine` 这一列先落下了，
> 哪天要建，历史数据是齐的。

# 第四条：预算从"次数"变成"钱"

`MAX_UNIT_A_PER_DAY = 5` 管的是跑几只。**它挡不住钱**：
一只材料特别多的票能吃掉另一只十倍的 token，
五次调用之内就可能花掉预想的几倍，而次数账上完全正常。

所以钱是**第二道闸**，规矩和次数那道一样：

```
从磁盘上的账数出来      中途重启不清零
先记账，再花钱          跑一半崩了，那一次也算花过了
钱花完了要说是钱        "今日花费已达上限"≠"今日研究预算已用完"
                        两句话处理方式相反：一个明天再来，
                        一个是要么加钱、要么换便宜的引擎
```

`token` 是**事实**（API 回报的），`usd` 是**按一张带日期的价目表估的**，
两者分开记、分开印：

```
引擎 claude:claude-sonnet-5　in 26,113　out 4,802　估算 $0.1002 / 上限 $5.00
```

**不在价目表里的模型 → 0 元，但那不是"免费"，是"不知道"。**
两者都印 0，含义相反，所以有 `priced` 这一位，而且会点告警。

## 漏网一：远程那条路**够不着**

本地失败那条测得到（连接被拒）。远程失败测不到——
**没 key 会更早地停，有 key 又会真的联网**。于是那一半从来没被验证过，
而它恰恰是换成 Claude 之后每天都会发生的那一半。

改法：把 `httpx.post` 换成会抛的假货，直接打那条路；
顺带把"空回复"也测了（空回复不是"它没话说"，是这一次没成）。

## 漏网二、三：**我自己的注释满足了我自己的断言**

两条都是子串碰撞，而且都是我写的说明文字造成的：

```
断言                              被什么满足
"llm.engine()" in unit_a 源码      我写的那行注释：「只有 llm.engine() 这一处决定」
"engine=oll.spec" in unit_a 源码   UnitAAdvice(...) 里的那一份
                                   —— 而删掉的是**论点台账**那一处
```

第二条尤其难看：`engine=oll.spec` 在文件里有两处，
一处进 `UnitAAdvice`（报告上看得见），一处进 `thesis_store.record`
（**半年后要回答"这条论点是谁写的"的那处**）。断子串的话，
删掉后者照样绿 —— 而那正是唯一有用的那处。

这是这个会话里第三次栽在同一个坑。两条都改成走 AST：

```python
找到 build_unit_a 里对 oll 的赋值，断它调的是 engine()
找到 thesis_store.record(...) 那次调用，断它的关键字里有 engine
```

# 一件要你自己决定的事

这是你定过的红线的改动。你原来说的是「本地模型 only」。

送出去的是：**公开新闻标题 + 400 字正文片段、SEC 文件、公开行情面板、代码。**
不送：持仓、净值、论点台账、账本、复核台账。

但有一样容易被忽略：**"今天研究哪 5 只"这个名单本身就是信息。**
它不是持仓，但它泄露你的关注方向。这是从"本地模型 only"往外走的
实际代价，我把它写在这里，不让它悄悄发生。
