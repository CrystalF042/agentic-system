## 相关性闸认标题里有没有标的名,而公告标题用的是**公司法定名称**

```
AMD   → ADVANCED MICRO DEVICES INC 8-K    不含 "AMD"
MU    → MICRON TECHNOLOGY INC 10-Q        不含 "MU"
KLAC  → KLA CORP 8-K                      不含 "KLAC"
NVDA  → NVIDIA CORP 8-K                   不含 "NVDA"
TSM   → TAIWAN SEMICONDUCTOR MFG CO LTD   不含 "TSM"
```

我把你那 10 只票逐个跑了一遍别名匹配:

```
NVDA  ✘ 被丢掉      AVGO  ✘ 被丢掉      LRCX  ✘ 被丢掉
AMD   ✘ 被丢掉      TSM   ✘ 被丢掉      AMAT  ✘ 被丢掉
MU    ✘ 被丢掉      QCOM  ✘ 被丢掉      KLAC  ✘ 被丢掉
ARM   ✔ 过
```

**10 只里 9 只的公告在这一步被全部丢光。** 唯一活下来的 ARM 是**侥幸**——
"ARM" 恰好是 "Arm Holdings plc" 的子串。所以 ARM 那 8 条实质材料不是它今天
新闻特别多,是**只有它的公告没被误杀**。

这也解释了为什么 ARM 一枝独秀:它拿到的是别人本来也该拿到的东西。

### 而进料行完全看不出来

```
采集 73 条（含 EDGAR 一手披露 8 条） → 去重 47 → 相关 17 → 前 10 条进闸门
```

73 → 17 这个降幅里,那 8 条公告已经全没了。数字全都正常,没有一处异常。

---

## 改法:按 CIK 取回的公告不过相关性闸

这些公告是**按 CIK 取的**——身份由 SEC 自己的公司标识确定,不需要再用字符串猜。
相关性闸防的是新闻里"顺带提一句"的噪音,按 CIK 取回的公告根本不属于那一类。

**普通新闻源照旧要过闸**,规则本身没被削弱,有测试守着这一条。

进料行现在把公告的存活过程分开报:

```
采集 73 条（EDGAR 一手披露 8 条 → 过相关性 8 → 进闸门 5） → 去重 47 → 相关 25 → …
```

全军覆没时会变成:

```
（EDGAR 一手披露 8 条 → 过相关性 0 → 进闸门 0　⚠ **公告全部未通过相关性闸**）
```

**这一行本来就该在**——它在的话,build92 那轮我一眼就能看出问题,
不用去反查别名匹配。

## 这轮之后预期会怎样

九只票第一次真正拿到自己的公告。合理预期:

- **AMD / MU / KLAC 这三只应该会动。** 它们前几轮一直是 0,而 0 的原因
  现在明确了——不是没有公告,是公告被丢了。
- **ARM 可能反而不再一枝独秀**,因为别人也拿到了同样的东西。
- 实质占比大概率再上一个台阶。

**但要注意一个新的可能性**:如果某只票的实质材料一下子全变成公告
(比如 8/10 都是 8-K),那说明新闻类材料被公告挤出了前 10。
那不一定是坏事——公告本来就该排在评论前面——但值得看一眼,
因为辩论手里如果全是表单,论述会很干。到时候把 `MATERIAL_CAP` 从 10 提到
15 就行,那是个一行的常数。
