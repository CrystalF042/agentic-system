## 加固一:抓公告正文,而且必须带 SEC 的 User-Agent

公告条目原来只有标题和一行占位:

```
标题   NVIDIA CORP 8-K (2026-08-28)
正文   SEC filing 8-K filed 2026-08-28.
```

这样的材料进了辩论,论据只能引用到"有一份 8-K"。所以现在会去抓每份公告的
**正文**(前 5 份,SEC 限速 10 req/s,这点请求很宽裕)。

**必须用 `httpx` + `SEC_USER_AGENT` 自己抓,不能交给 `trafilatura.fetch_url`**
——后者用自己的 UA,sec.gov 直接 403。而 403 的表现是"这份公告没有正文",
和"这份公告确实没内容"长得一模一样。

---

## 加固二:**采集器自己写的那行字,不能被当成外部证据**

这条是查的时候才发现的,比接 EDGAR 本身更值得说。

`fetch_edgar_recent` 给每份公告造的占位串是 `SEC filing 8-K filed 2026-08-28.`
——而闸门的文本规则里,`8-K` 是硬锚点、`filed` 是完成动作。于是:

```
只有标题                    → 背景
标题 + 我们自己写的占位串    → 实质 ✓
```

**判的不是公司做了什么,是我们自己写下的那句话。** 后果是每一份公告都自动
过闸,哪怕一个字的内容都没取到——闸门开了,而辩论手里是一条什么都没说的存根。
报告会声称有基本面依据,而它没有。**那比闸门不开更糟。**

所以现在实质度多了一条来源路径,而它的作用**主要不是提升公告,是卡住空公告**:

```
取到正文的公告(≥200 字)   → 实质
只有表单号的公告          → 背景,并写明「一手披露,但正文未取到 —— 不足以作为论据」
```

有一条测试专门守着这个,而且它先断言"占位串确实会骗过纯文本规则"——
不先证明这一点,后面那条断言什么也证明不了。

**按来源降级新闻源那条老原则没有变**:Zacks / TipRanks 不会因为是它们就被
降级,Reuters 也不会因为是它就被升级。新增的这条守的是另一个方向——
**不把系统自己的输出当成外部证据**。

## 进料行会多一段

```
采集 91 条（含 EDGAR 一手披露 8 条） → 去重 37 → 相关 27（补正文 22 条） → 前 10 条进闸门（截掉 17 条；…）
```

如果某只票的 EDGAR 取不到,`status` 里会写明 `EDGAR: 失败(...)` 或
`ok（8 份，其中 0 份取到正文）`——**取到几份正文是单独报的**,
因为那个数直接决定有几条能算实质。

## 装完之后怎么读

重点看两件事:

1. **进料行里 EDGAR 的条数和"取到正文"的份数。** 如果正文份数一直是 0,
   说明 SEC 那边在拒我们,`SEC_USER_AGENT` 需要换成带你真实邮箱的字符串
   (`.env` 里设 `SEC_USER_AGENT="你的名字 你的邮箱"` —— SEC 要求可联系)。
2. **AMD / MU / KLAC 这几只有没有变。** 它们前几轮一直是 0,
   如果接了一手源还是 0,那基本可以确认:今天这几家确实没发公告,
   闸门是对的。
