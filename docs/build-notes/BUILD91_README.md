## 重扫暴露了什么

对比两轮:

| | build89 | build90 | |
| --- | --- | --- | --- |
| NVDA | 实质 0 | 实质 1 | ✅ 截断修复起作用了 |
| TSM | 实质 0 | 实质 1 | ✅ 同上 |
| **AMD** | **实质 1** | **实质 0** | ❌ **反而丢了** |
| **LRCX** | **实质 1** | **实质 0** | ❌ **反而丢了** |

修截断的同时,把另外两只的实质材料挤掉了。

### 为什么

build90 里,**排序看的是标题,闸门看的是"标题 + 模型生成的摘要"**。
两段不同的文本,两个判定,于是在**两个方向**上都出现了分歧:

```
AVGO      相关材料分档写着「实质 1」,闸门却判「实质 0」
AMD/LRCX  分档写着一条实质都没有,而闸门原本是能判出 1 条的
```

我在 build90 的代码注释里把这写成"一个已知的近似",还加了一句
"闸门始终是唯一的判定权威"。**那句话是错的**——排序决定谁能进闸门,
它一旦判错,闸门就再也没机会看到那条材料。一个只在排序里悄悄生效的近似,
刚好是没人会发现的那种。

### 改法:两边看同一段文本

新增 `unit_a.basis_text(n)` = **原始标题 + 正文前 400 字**,不含任何模型产物。
排序调它,闸门也调它(材料上新增 `basis_text` 字段,`material_gate.basis_of()`
统一取值)。有一条测试专门守着这个不变量:同一条材料,两边的判定必须逐条相同。

真实例子(就是 AMD 那一类):

```
标题        AMD in the spotlight this week            → 背景
标题+正文   ...announced it has completed the
            acquisition of ZT Systems for $4.9bn      → 实质
```

## 顺带修掉一个更深的问题:闸门原来在判 LLM 的输出

材料的 `text` 是「原文标题 + **Ollama 生成的一句话摘要**」,而闸门就是拿它判实质度。

两个后果:

**一、一个号称零 LLM 的闸门,输入里有 LLM 的产物。** 同一批新闻,摘要措辞一变,
闸门结论就可能变——可复算没了。更循环的是,**这个闸门决定的正是"要不要启动
LLM 辩论"**。

**二、摘要只对入选后的材料生成**,所以入选的和被截掉的用的是两种不同输入,
两边分档根本不可比——而报告上还印着"被截掉的都不是实质"。那句话在 build90
里是一句**没有依据的安慰**。

现在闸门判 `basis_text`(源头文本),摘要只负责给人读。

## 补正文的名额挪到了该花的地方

判定要看正文,而正文靠 `enrich_fulltext` 抓。原来它跑在**去重和相关性清洗之前**,
`top_n=10` 那十个名额有相当一部分花在了后面会被丢掉的条目上——
等到真要判定时,手里只剩标题。

现在清洗之后再补一次(`enrich_news_fulltext`,25 条),名额花在
"哪十条能被看见"这个决定上。进料行会显示补了多少条:

```
采集 91 条 → 去重 37 → 相关 28（补正文 22 条） → 前 10 条进闸门（截掉 18 条；…）
```

---

## 我的探针第六次踩了同一个坑

那条"补正文必须排在截断之前"的探针,第一版是这么写的:

```python
a = src.find("enrich_news_fulltext")
b = src.find("_rank_by_substance")
return a < b
```

而代码上一行的注释正好是 `# 顺序很重要,见 _rank_by_substance` ——
**`find` 命中了注释,不是代码**,于是顺序判反、误报。

这个仓库在"探针 grep 到解释该修复的那句注释"上已经栽过五次,这是第六次。
现在那条探针走 AST:取 `Call` 节点的行号比先后,取 `ranked[:MATERIAL_CAP]`
这个 `Subscript` 的行号定位截断点。**只要还在比字符串,就还会有第七次。**

## 装完之后怎么读新的扫描结果

三件事分开看:

1. **NVDA / TSM 的实质材料是真的**(build90 已证明,截断确实在挡)
2. **AMD / LRCX 应该回来**(build91 修的就是这个)
3. **AVGO / MU / ARM / KLAC 大概率还是 0** —— 它们在 build90 里
   相关材料 16–30 条、分档几乎全是「背景」。那不是闸门严,是**源的问题**

第 3 条才是接下来要处理的:229 条相关材料里 198 条是背景。
Google News / RSS 给的是评论和分析,不是一手事件。要让实质材料变多,
方向是接**一手源**(SEC EDGAR 的 8-K/10-Q、公司 IR 新闻稿、交易所公告)——
那些按定义就是已发生的事实,而且免费、结构化。
