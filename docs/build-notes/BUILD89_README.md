## 一条新命令

```
CIO_MARKET=us .venv/bin/python run_book.py
```

它按固定顺序做四件事:

```
1. 公司行为   拆股改股数与成本价,分红入现金
2. 盯市       未复权收盘价 × 股数 → NAV,写进净值曲线
3. 对账       三条恒等式,任一不成立就**不出盈亏表**
```

其他用法:

## 顺序为什么是硬的

**公司行为必须在盯市之前。** 反了的话,盯市会拿**拆后价格**乘**拆前股数**——
那一天的市值凭空翻几倍或掉四分之三,而它是一个完全正常的数字,没有任何报错。

这也是这个 build 存在的主要理由:**公司行为是所有自建账本最常见的死法。**

4:1 拆股当天:

```
账本说   100 股 @ $800
市场说   $200
```

持仓瞬间显示 **−75%**。净值曲线上只多一个巨亏日,第二天照常盯市,那个坑
永远留在曲线里。分红更隐蔽:不记的话组合白少一笔收入,而基准(复权序列)
是含息的,于是超额收益被系统性低估——**每年差一两个百分点,长期就是全部的结论**。

现在两件事都是**显式事件**,写进 `book_corp_action`,看得见、可回溯、可对账:

```
拆股   股数 × ratio,成本价 ÷ ratio,零头按除权日价折现金
分红   现金 += 股数 × 每股金额
```

**取不到除权日价就不应用这次拆股**,并让该标的在盯市时标缺价。硬着头皮取整
会静默吞掉零股价值;而"拆了但账本没拆"比不拆更危险。

## 每日对账:三条恒等式

```
1  现金 + Σ(股数 × 盯市价) == NAV
2  初始资金 + Σ(交易现金流) + Σ(公司行为现金) == 当前现金
3  每个持仓的股数,能被 trades 加公司行为解释出来
```

任何一条不成立,**本轮不出盈亏表**——不是"标个警告"。

一份带警告的盈亏表还是会被读、被相信、被拿去做决定。对账失败的含义不是
"某个数字可能有点问题",是**这本账现在自相矛盾**;在矛盾解决之前,由它算出的
任何收益率都没有意义。

真跑出来长这样:

```
每日对账　2026-08-31：PASS　三条恒等式全部成立
  [通过  ] 现金 + 持仓市值 == NAV
         现金 96,577.00 + 持仓 3,492.00 = 100,069.00　NAV 100,069.00
  [通过  ] 初始资金 + 交易现金流 + 公司行为 == 现金
         初始 100,000.00 + 交易现金流 -3,423.00 + 公司行为 0.00 = 96,577.00　账上现金 96,577.00
  [通过  ] 持仓股数能被交易与公司行为解释
         2 个持仓的股数都能被交易与公司行为解释
```

每条都把两边的数字印出来,失败时直接看差额去找。

## 净值曲线里的两处"拒绝编数"

**缺一个价 → 当天 NAV 记 NULL,`complete=0`。**

不是"按剩下的算"。漏掉一只票的市值,NAV 会小一截,曲线上不会有缺口,
只会出现一个凭空的亏损日,第二天又"涨回来"。两个假的极端值,
而每一个数字看起来都正常。

```
2026-08-28      100,000.00        0.00     0.00%    3.4%
2026-08-29      100,006.00        6.00     0.01%    3.4%
2026-08-30            不可计算           —         —       —  ⚠ 缺价 1 只
2026-08-31      100,069.00           —         —    3.5%
```

**前一日不完整 → 当日盈亏不计算。** 拿今天的 NAV 减三天前的 NAV,得到的是
三天的变动却挂在今天头上——不会错到离谱,只会让某天看起来特别好或特别糟,
最难发现的那种。

## 跑出来才发现的一个缺陷

先写 08-31,再回填 08-28 和 08-30 之后,08-31 那行还显示"当日 +2200"——
因为写它的时候前面几天还不存在,它算的其实是**相对初始资金**。
数字完全正常,只是**答非所问**。

修法是把 `day_pnl` 当作**派生量**:每次盯市后整条曲线重算一遍,让
"当日盈亏 = 相对上一有效净值"这个定义在任何写入顺序下都成立。
顺带加了一条:**盯市日早于开账日直接拒绝**——账本还不存在的日子不该有净值。

## 基准与超额

基准用**复权** SPY 收盘价,那就是含息总回报序列。这是全系统**唯一一处
账本侧刻意使用复权价**的地方,因为这里要的正是"含息的累计回报",
不是"某天的成交价"。

**基准取不到就不算超额**,不用价格收益顶替。

**超额永远和平均仓位一起印:**

```
基准 SPY（TOTAL_RETURN(adjusted close)）累计 1.82%　超额 -1.75%　← 当前仓位 3.5%
  （仓位远低于 100% 时,和满仓基准比出来的超额不说明选股能力,只说明没投出去。）
```

## 盈亏表里那两行"管人"的字

每个持仓旁边有**距上次复审多少天**和**当初写下的失效条件**:

```
AVGO        6 股　成本 305.50　现价 312.00　市值 1,872.00　浮盈 39.00（2.13%）　权重 1.87%
       持有 3 天　上次复审 2026-08-28（3 天前）
       ⚠ 没有记录失效条件 —— 无法判断该在什么情况下认错
```

人工做投资最经常的失败不是算错,是忘了当初为什么买、说好什么时候认错。
这两行几乎零成本,却是整套论点台账真正产生约束力的地方——
其余所有东西都在算数,**只有这一条在管人**。

（上面那条警告是真的:AVGO 是演示数据,没有对应论点。真实流程里
`run_unit_a.py` 会写下失效条件,这里就会把它们并排印出来。）

## build89a 补丁修了三件事（都是我自己写出来的）

**1. `run_book.py` 崩在 `KeyError: 'nav'`。** `valuation.mark()` 的早退路径
只返回 `{"ok": False, "note": ...}`,调用方一句 `m['nav']` 直接炸——
**而且炸在调用方那一行,看起来像调用方写错了**。
现在 `mark()` 每条路径都返回同一组键,缺的值是 `None` 而**不是缺键**;
`run_book.py` 也先查 `ok` 再往下走。

**2. 探针「基准取不到 → 超额不计算」在你机器上红,在我这里绿。**
红的不是安装,是**探针自己**。它只传了 `bench_close=None`,而那个值同时表示
"没传"和"没有":你有网,SPY 取得到,超额算得出来,断言就不成立了。
**同一份断言在两台机器上测的是两件事。**
现在 `mark()` 多了一个显式的 `use_bench=False`,探针和测试都用它,
任何机器上结果一样。`test_book.py` 里 22 处也一并改了——那些用例
在你机器上本来也会去连 SPY。

**3. 根因:你的账本开账日是 2026-09-01,而今天是 08-31。**
那是我在 BUILD87 的例子里写死了一个未来日期,你照着填的。于是
**每一次盯市都会被"盯市日早于开账日"挡下来,而报错指向盯市、不指向开账**。

现在 `open_book()` 直接拒绝未来的开账日,并给了改正的口子:

```
CIO_MARKET=us .venv/bin/python run_rebalance.py --open-book --opened-on 2026-08-31 --reset-open-date
```

**只在这本账还没发生过任何事时生效**（没有交易、持仓、净值、公司行为记录）——
有记录之后再改开账日,历史区间和收益率的分母全变,而数字看起来仍然正常。
