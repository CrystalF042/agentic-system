## 一、政策层被我自己绕过了

`judge.py` 开头有一整节叫「语言理解 与 政策，必须切开」，写着表单号该不该开门
是 CEO 定的规则、不能交给模型。然后 `LLMJudge.judge_one` 的实现是这样的：

```python
def judge_one(self, text, source_name="", source_url=""):
    key = _key(...)                       ← 直接进缓存
    ...
    raw = self.chat(_TIER_PROMPT...)      ← 直接问模型
```

`is_primary` / `OWNERSHIP_FORMS` / `PRIMARY_MIN_CHARS` **一条都没走**。
文档里承诺的边界，代码里没有。

你昨天那次评测把它抓了出来：`SC 13G body=True` 期望「背景」，Claude 判「实质」。
**模型没有错**——它读到的是一份真实、有正文、依法必须披露的文件。
错的是这个问题根本不该由它回答。持股申报说的是**某个人卖了股票**，
不是这家公司发生了什么；把它当成"今天值得重新研究这家公司"，
闸门就退化成一个日历。这是 build95 定下的规则。

改法：来源与表单先走代码，命中就直接定档，**模型连问都不问**。

```python
pv = policy_verdict(text, source_name, source_url, self.name)
if pv is not None:
    return pv                    ← 走在缓存之前
```

验收用的是一个**被调用就抛异常**的假后端：结果仍然正确，就证明它没被调用。

## 二、`政策直判` 单独报，不算降级

新的一行输出：

```
  降级 0/75（0%）（模型不通或引文对不上 → 回落到规则）
  政策直判 7/75（9%）（来源/表单由代码定档，**没有问模型**）
```

这两个数不能合并。降级是**故障**（模型该跑而没跑成），政策直判是**设计**
（这条本来就不该问模型）。合成一个数，七份正常工作的公告会让评测报出"模型不通"。
——build104 那个缺陷的同一个家族，所以这次先把它分开。

## 三、混合判定器：模型判语言，规则留一票否决

你昨天那张表：

```
              规则      Claude
调参集        67/67     51/67
留出集        3/8       7/8
相关性        13/20     19/20
```

16 条分歧里 **13 条是模型更严、3 条更松**。三条更松的全是同一类：

```
AMD Enters a Sovereign AI Showcase, Not a Revenue Windfall    转折否定式
What KLA (KLAC)'s … Means For Shareholders                    解读体
SC 13G body=True                                              （政策，上面已修）
```

前两条是**评论体标题 + 事实性正文**——正是规则花了 build96 到 build100
四轮才收干净的那一类。规则在这上面是对的。

### 为什么不取并集

直觉上该做"两边谁说实质就算实质"，把那 13 条更严的也捞回来。**不能这么做。**

那 13 条里规则的"正确"，绝大部分是它在**自己的训练数据**上的正确——
调参集每一条都来自某个 build 的修复现场，规则见过它、而且是为它改的。
把这种正确并进来，等于把留出集刚刚量出的那份过拟合重新装回系统。
留出集从 3/8 到 7/8 的差距，量的就是这个。

### 所以否决只准往下压

档位以模型为准，规则只有**一票否决**，三个条件缺一不可：

```
模型判「实质」  且  标题命中硬标记  且  规则自己也不判实质
```

第三条让分句救援继续有效（`$2 Billion in Orders — Is ARM a Buy?`
后半句的荐股钩子不该杀掉前半句的在手订单）。
软标记（行情复述/股价预测）**不参与否决**——"价格动了"经常和真实原因
写在同一个标题里，build96 花了一轮把软硬分开，否决权不能把它又合回去。

现有 75 条语料上验过：满足否决条件的有 31 条，**其中没有一条的期望等级是
「实质」**。这不是"因为它不会出错所以安全"，是"如果它出错，语料会红"。

相关性整条交给模型：19/20 对 13/20，而且规则的错法是**认错**
（`It's` 被当成 ticker `IT` 的所有格，十个名额里六个是委内瑞拉石油和橄榄球赛程），
不是判得严不严。这里没有可以保留的规则优势。

## 四、`hybrid:` 与模型共用缓存 —— 重跑不花钱

```
python scripts/eval_judge.py --judge hybrid:claude:claude-haiku-4-5 --verbose
```

否决发生在**拿到模型答案之后**，所以混合判定问模型的问题和纯模型判定一模一样。
缓存文件名去掉 `hybrid:` 前缀，两者共用一份：你昨天那次评测已经把 88 条答案
存下来了，这次**一个请求都不会发**（离线验过：`claude:fake` 88 次 →
`hybrid:claude:fake` 0 次）。

两栏分数的差异因此只可能来自否决逻辑本身，不会掺进"模型这次心情不同"。

顺带修了一个会让这件事失效的坑：评测原来用
`getattr(jd, "_cache", None)` 去够私有字段落盘，包一层之后那句就够不着了——
**缓存从不落盘，下次重新调一遍模型，多花的钱不会有任何提示。**
`flush()` 改成接口的一部分。

## 五、装完的顺序

```
1  .venv/bin/python scripts/check_build.py                     130 项
2  .venv/bin/python scripts/test_judge.py                      21 项
3  .venv/bin/python scripts/eval_judge.py                      规则基线 67/67 · 3/8 · 13/20
4  .venv/bin/python scripts/eval_judge.py --judge hybrid:claude:claude-haiku-4-5 --verbose
```

第 4 步该看的三个数（预期，**不是保证**）：

```
调参集   51/67 → 54/67 左右    两条评论体被否决 + SC 13G 归政策
留出集   7/8   → 7/8           那条 Might Change The Case 标题里一个硬标记都没有，
                               规则也不认识它，否决帮不上忙
相关性   19/20 → 19/20         整条交给模型，不变
```

**留出集不动是预期内的。** 这次改的是"模型太松"的那一侧，而留出集上模型已经
接近满分了。真正的收益是：调参集不再退化，同时留出集保住 7/8——
也就是**拿回规则的严格，但没有拿回它的过拟合**。

跑完把三个数发我，尤其是 `规则否决 N/75` 那一行。
