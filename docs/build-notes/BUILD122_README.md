# 第一条：那道闸由代码保证绕不过去

你上次的更正我记着：**「一道从没否决过的闸就拆掉」只适用于流程闸，
不适用于资本授权闸。** 流程闸按否决率考核，授权闸按"它还在不在"考核。

所以这一版把它从"我们的约定"变成"代码不允许"，钉三层：

```
状态机   queue.LEGAL 里 APPROVED **只有一条入边**：来自 PENDING_APPROVAL
源码     自动那五个模块（pipeline / scheduler / router / propose / research_run）
         里，走 AST 找出每一个 transition() 调用，**不许有把状态改成 APPROVED 的**
跑一遍   全链跑完，终点是 PENDING_APPROVAL，且没有任何条目自己进了 APPROVED
```

第二层是关键：光有状态机不够——状态机只说"这条路存在"，
说不出"自动化有没有走它"。AST 那条断言说的是**代码里根本没有那个动作**。

# 第二条：口径不符 ≠ 风险高

`risk_officer.check_units` 在测量单位不对时抛 `ValueError`。
顺手 catch 成"这只票有风险"是最糟的一种错：

```
真实情况：我们没法评估它
记下来的：风控认为它危险
```

**一个错的原因比没有原因更糟**——它把人叫去查一个不存在的问题。

所以它单独一类（`unmeasurable`），既不是否决、也不是研究失败，
报告上有自己的一行，条目转 `FAILED` 明天重来，note 里**写死它不是风险判断**。

---

# 第三条：否决是告警，不是备注

CRO 否决是**稀有事件**。报告有六节，一条稀有的话排在第五节第三行，
半年之内人就会养成只看第一行的习惯——**那时它等于没有发生过**。

所以心跳这一版多了 `alert()`，和 `note()` 分开，印在报告**最上方**：

```
CIO 流水线心跳　2026-09-05

⚠ **本次有 1 条需要你现在就看**
   · [风控与仓位] **CRO 否决 AMD**：已实现波动率(60日年化) 92.31% 触及否决线 80.00%　—— 这只票本轮不进提案

[技术快照] 完成 ...
```

两条附带规矩：

```
告警必须写理由      说不出原因的告警比没有告警更糟
有告警而推送失败    大声报错 —— 日常心跳掉一次第二天补上，告警掉了就再也不会自己出现
```

**一道从没否决过的风控闸，和一道否决了但没人看见的风控闸，
在结果上是同一道闸。**

# 第四条：算不出仓位是一个结论，不是一次消失

PC 说"给不出仓位"（σ 太高 / 上限压到 0 / 材料档位不够）落新的终态
`NO_TRADE`，带原因、进计数。

**和 `VETOED` 严格分开**：

```
VETOED     风控拦下的 —— 这只票现在不许碰
NO_TRADE   风控放行，PC 算完给不出仓位
```

合成一个的话，半年后答不出"风控那道闸到底拦下过什么"——
而那正是判断要不要拆闸的唯一依据。

更要紧的是不许它无声消失：**一条走到这里就从计数里蒸发的记录，
和一条根本没进来的，看起来一样。**

# 第五条：队列和提案库必须对得上

新增两格：`Item.proposal_id` / `Item.portfolio_id`，
每次跑完做一次对账，不一致就告警：

```
对账：队列待批 3　提案库待批 2　⚠ **对不上**
```

没有这一格的话，"队列里 3 条待批"和"提案库里 2 条待批"是两个谁也说不清的数，
**而第三条去哪了，没有任何一处能回答。** 两个数长期没人对，
第一次对不上的时候没人知道是今天开始的还是三个月前。

状态和提案号是**一次跃迁里一起写**的——分两次写就存在中间那一刻：
状态已经是"待批准"，而提案号还是 0。

# 顺手做的两次合并：不许有两份等价实现

build121 刚被这个形状咬过（那句"没有新的基本面事实"判了两处，
测得到的不是跑起来的那处）。这一版有两处会重蹈覆辙，先合了：

```
CRO 的口径换算    run_pc.py 私有的 _measures_for  →  cio/cro_inputs.py
落提案那六步      run_rebalance.py 的一整段        →  cio/propose.py
```

第二个合并里有一条纪律必须跟着搬进库：**先序列化，后落库。**
顺序反过来存在这样一条路径——

```
提案已写库 → 序列化炸了 → 界面判定失败 → 用户点重试 → 库里两条一模一样的提案
```

它原来住在 `run_rebalance.py` 里。留在入口里，**另一个入口就会漏掉它**。
现在它是 `propose.for_run(before_record=...)` 这个钩子，
有一条用例专门断"钩子被调用时库里一个字都还没写"。

## 顺带：我自己就写出了那盏常亮的灯

第一版的告警条件是

```python
if res["propose_status"] and res["propose_status"] != "completed":
```

而"今天没有一只走到目标权重"——**最常见的正常状态**——会让
`propose_status = "no_targets"`，于是这盏灯**每天都亮**。

用例 `t_a_veto_is_an_alert_not_a_note` 当场把它红了：那次断言要求
"只有一条告警"，实际有两条。**常亮的灯 = 不亮的灯**——
人学会忽略它之后，真正需要看的那天也会被忽略。
