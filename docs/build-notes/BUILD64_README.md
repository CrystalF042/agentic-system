## 那份 PDF 暴露的真 bug —— build63 也有

你这份报告在**同一页上自相矛盾**：

```
正文：  **失效条件**（若发生即视为论点失效）
        - 毛利率跌破60%   - 运营利润率低于50%   - 营业收入同比增长转负
        - 自由现金流收益率升至5%以上   - 总负债/总资产超过30%   - Beta上升至2.0以上

下一节：失效条件（什么一旦发生，论点即应视为失效）
        （本轮未产出可核对的失效条件）
        ⚠ 没有失效条件的论点此后无法被证伪。这本身值得注意…
```

**原因**：本地模型这次把小节写成 `**失效条件**` 而不是 `【失效条件】`。
解析器只认 `【】`，于是**催化剂和失效条件双双解析出 0 条**。

**真正的损失不在版面上**：台账存了 0 条失效条件——
**明天的失效复检拿到的是空的**，而且永远不会报错。
和 build61 那个中文分词的坑是同一类：不报错、看起来正常、信息没了。

现在五种写法都认：`【失效条件】` / `**失效条件**` / `### 失效条件` /
`4. 失效条件` / `失效条件：`，并允许标题后跟括号说明。

裸标题（`4. 失效条件`）只按**已知小节名**匹配，不用"短行即标题"这种通用规则——
`毛利率跌破60%` 也是一个 10 字无空格的短行，通用规则会把正文当标题、把小节切碎。

**顺带修回一个回归**：给终止符加 `$` 锚点会让 `结论=看多|中` 混进失效条件列表
（旧版正是靠没有锚点才挡住的）。已加测试锁死。

## 「解析失败」和「模型没写」必须分开说

原来两种情况印的是同一句话，而它们**结论相反**：

| 情况 | 该说什么 | 该做什么 |
| --- | --- | --- |
| 模型真没写 | "这个论点此后无法被证伪，值得注意" | 这是对分析师的判断 |
| 解析器没抓到 | "解析失败，原文里其实有 6 条" | 这是我的 bug，要修代码 |

把后者说成前者，就是**拿自己的 bug 去指责模型**，而且会让你以为回路在工作。
现在正文里出现了"失效条件"却一条都没解析出来时，报告直接写：

> ⚠ 综合文本里出现了「失效条件」，但解析器一条都没取到——
> 这是**解析失败**，不是模型没写。请看上方【一部观点】原文，并把这份报告发回给开发修解析器。

## 还修了

**markdown 表头行不算论断。** `| 对方论点 | 我方反驳（仅引用面板数据） |`
是表格栏目名，却被逐行核验器标成 ⚠未核实。
判据刻意窄：首尾是 `|`、单元格都短、**且没有任何数字**——有数字的就是数据行，照常要出处。
