## 这次冻结了什么

### 1. 批准的是**股数**，不是权重

T 收盘后用 T 的 NAV 和 T 的收盘价算出 `target_shares`，CEO 批的就是这个整数，
T+1 开盘按实际开盘价成交它。

反过来做（批权重、执行时按新价重算股数）看起来更"准"，但批准的东西和执行的
东西不是同一个，审批就失去意义了。更糟的是开盘跳空 −8% 时系统会自动买更多股
（目标金额 ÷ 更低的价格）——**这个行为没有任何人批准过。**

真实世界里 PM 批的是"买 1200 股"，不是"买 1.8% 然后系统看着办"。

### 2. 成交价基准 `T+1_OPEN`，写死并印在报告上

用 T 日收盘价成交，等于用当天的信息买当天。回测会好得莫名其妙，而没有一处报错。

### 3. 批准会**过期**

一次批准是基于某一天的 NAV 和价格算出的股数。周五批的、周三才执行，拿三天前
的股数去成交完全合法：格式正确、账本欣然接受，**错的只有结果**。
所以有效期 4 天（覆盖周末 + 一个假日），过期自动作废、必须重新提案。
每次跑 `run_rebalance.py` 会先把过期的清掉。

### 4. 只交易差额，且有不交易门槛

Δ = 目标股数 − 现有股数。开仓/加仓/减仓/清仓统一成一个逻辑。
门槛 = max(NAV × 0.25%, $200)，低于门槛不动——不设的话每天会产生一堆 2 股、
5 股的调仓，真正重要的调整淹在噪音里。**清仓例外：目标 0 永远执行。**

## 最重要的一条：**"没有目标" ≠ "目标为 0"**

这是整个 Build 1 的核心，也是最容易写错的一行代码：

```python
target = targets.get(ticker, 0.0)      # 绝对不要这样写
```

`.get(x, 0.0)` 把"本轮没对它做判断"和"本轮判定应该清仓"折成同一个值。
于是一只只是**今天没有新材料**的持仓会被安静地全部卖出——
指令格式完全正确，账本欣然接受，没有任何一处报错。

现在的映射只有一处（`rebalance.target_from_decision`）：

| 台账里的那条决策 | 读作 | 动作 |
| --- | --- | --- |
| `veto = 1` | 目标 0 | **清仓**（风控说了不该持有） |
| `w_final` 有值（含 0.0） | 目标 = 该值 | 按差额买/卖 |
| `w_final` 为空、未否决 | **无目标** | **维持不动**，并标出多久没复审 |

第三档涵盖：Gate 材料不足、Gate 未记录、测量口径不符。这三种都**不是**卖出，
是"我今天没有材料来重新确认这个仓位"。

配套的还有三条同类保护：

- **取不到价 → `NOT_PRICED`**，不是目标 0。否则一次取数失败变成一道清仓指令。
- **目标不足一股 → 维持**，不是清仓。取整到 0 股不等于判定清仓。
- **持仓久未复审 → 报告上标出来**（默认 10 天）。人工做投资最常见的失败不是
  算错，是忘了当初为什么买、说好什么时候认错。

## 事前合规：查的是**成交后**的组合

真实机构里这一步叫 pre-trade compliance，问的是"如果这批单子全部成交，
会不会破限"。所以它必须在**批准之前**——批完再查只剩两个选择：撤单
（那批准是什么意思），或者带着破限过下去。

六项登记在册，现在能算两项：

| 检查 | 状态 |
| --- | --- |
| 买入所需现金不超过可用现金 | 已实现 |
| 成交后总仓位 ≤ 100%（不加杠杆） | 已实现 |
| 单一行业 ≤ 20% | **未评估**（Build 4） |
| 单一主题 ≤ 25% | **未评估**（Build 4） |
| 组合年化波动 ≤ 12% | **未评估**（Build 4，需相关矩阵） |
| 单票 ≤ 20 日均额的一定比例 | **未评估**（Build 4） |

**有未评估项时整体结论是 `PARTIAL`，绝不会是 `PASS`。**
差别不是措辞：`PASS` 会被读成"风控查过了，没问题"，而真相是六项里只查了两项。
一个只做了三分之一的检查报告"通过"，比它不存在更危险——不存在时人还会自己去看。

## 账本换成美股口径

| | 旧 `cfo.db`（封存） | 新账本 |
| --- | --- | --- |
| 代码 | 6 位数字 | 字母 ticker（6 位数字会被**拒收**） |
| 每手 | 100 股整手 | **1 股** |
| 费用 | 双边佣金 + 印花税 | 零佣金、零滑点（字段存在并显示为 0） |
| 基准 | 沪深300 | SPY，**含息总回报** |
| 货币 | ¥ | USD |

两个细节值得单独说：

**滑点记 0 而不是拍一个 5bps。** 美股零佣金是真实的；编一个滑点看着像建模，
其实是猜，而且会让 P&L 没法证伪——收益差 0.3%，你分不清是策略还是那个拍出来的数。

**基准必须含息。** 组合会收到分红（Build 3 记为现金入账）。拿 SPY 的价格收益
去比，等于让组合白拿分红而基准不拿，凭空多出每年约 1.5% 的假 alpha。
这条现在只是**写进账本的要求**；Build 3 在能兑现之前必须拒绝输出超额收益。

**账本用未复权价**（`marks.PRICE_BASIS = RAW_UNADJUSTED`），和测量刻意不同。
复权价会**回溯改变**：下个月发一次股息，今天这根 K 线的复权价会随之下调，
于是账本里的成本价和数据源对不上了——而两边都没有错。
拆股与分红改为 Build 3 里显式的公司行为事件。

## 一个真被测出来的浮点缺陷

NAV 100,000 × 权重 1.8% ÷ 价格 180 的真值是整 **10 股**。
但二进制里 `100000 * 0.018 = 1799.9999999999998`，除以 180 得
`9.999999999999999`，直接取整就是 **9 股**。

这个错永远只朝一个方向：**少买**。每一笔都少一点点，账本永远比目标略轻，
表现为一段解释不了的持续跑输——而每一步计算都"没有错"。
现在取整前加 1e-9 容差，并有探针守着。
