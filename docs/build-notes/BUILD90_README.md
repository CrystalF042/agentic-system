## 一、截断:实质度原来在错误的时间判

你那轮扫描里,**TSM / ARM / KLAC / AMD 四只整整齐齐都是 10 条**。
那不是巧合,是撞上了上限。代码是这样的:

```python
news = sorted(news, key=lambda n: n.score, reverse=True)[:15]
news = _prefilter(news, info)[:10]      # ← 硬上限 10
```

排序用的是**相关性分数**,而**实质度是截断之后才判的**。

于是一条真有增量事实的材料,只要相关性排在第 11 位,就永远到不了闸门。
而报告上写的是「10 条材料,实质 0」——**读起来是"今天确实没东西",
真相是"我们只看了其中 10 条"**。截断本身不可见,被截掉的东西也不可见。

### 改成:先清洗 → 按实质度排序 → 最后才截断

```
采集 → 去重打分 → 取前 40 进池 → 相关性清洗 → **按实质度排序** → 前 10 进闸门
```

排序键是 `(实质度档位, 相关性分数)`——实质材料永远排在前面,
同档之内仍按相关性。分类是纯正则、零 LLM,多判三十条的成本可以忽略,
而它决定的是**哪十条能被看见**。

**一条纪律:排序调的是 `material_gate.classify` 本身,不是另写一套近似规则。**
测试的验证办法是把 `classify` 换掉,看排序是否跟着变——跟着变才说明它真在调。
两套规则一定会漂移,而这一套只在排序里悄悄生效,漂了没人会发现。

### 截断现在看得见

每只票下面多一行:

```
AMAT     ◐ 可跑       材料偏薄（7 条材料,实质 1）
    采集 31 条 → 去重 22 → 相关 14 → 前 10 条进闸门（截掉 4 条；相关材料分档 实质 1、背景 9、无实质 4）
```

汇总多一行:

```
相关材料 96 条,其中 26 条因每只上限 10 条未进闸门（实质材料优先入选,被截掉的都不是实质）
```

万一哪天实质材料真被截掉了,那行会变成 **⚠ 其中 N 条是实质材料** ——
正常不该发生,但守着这条才能在规则回退时立刻发现。

### 重扫之后才能判断闸门严不严

改之前,「实质 0」这个数字**同时包含**两种情况:真的没有增量事实,
和有但没让闸门看见。改完再扫,这个数字才是干净的。

我的预期:NVDA / AVGO / MU / QCOM 那几只本来就没到上限(7/4/5/5 条),
它们的结果不会变——**那几只是真的材料少**。会变的是撞了上限的那四只。
两类要分开看。

## 二、测试断网闸(抄 Vibe-Trading 的 `pytest-socket`)

一条会悄悄联网的断言,**在两台机器上就是两个测试**。

build89a 那次误报就是这么来的:探针「基准取不到 → 超额不计算」在我这里绿、
在你机器上红。红的不是代码,是探针自己——它把 `bench_close=None`
同时当成"没传"和"没有",于是有网的机器走取数分支、无网的走跳过分支。

现在 `scripts/_no_network.py` 在每个测试脚本最上面被 import,**两层**:

```
第一层  Python socket        拦住 httpx / requests / urllib
第二层  代理环境变量指向死端口  拦住 curl_cffi(yfinance 用的就是它)
```

**第二层不是多余的。** yfinance 走 `curl_cffi`,它在 C 层自己开连接,
**完全绕过 Python 的 socket 模块**——只焊第一层的话,测试里那句
`yf.Ticker(...)` 照样出网,而且拦不住还不报错。正是我们要防的那种
"看起来防住了"。

效果:全套测试现在 0.1–1 秒跑完,输出里再没有 yfinance 的告警噪音,
而所有降级路径(缺价、等待开盘、基准取不到)**都在断网状态下被真实测到**——
那些路径本来就不该靠拔网线才能测。

逃生舱:`CIO_TEST_ALLOW_NET=1`,只在你明确想跑一次真实取数时用。

## 顺带修的一条断言

`test_unit_a.py` 里检查 `collect_materials` 返回键是否齐全的那条,
原来只认 `return {...}` 这种直接返回字面量的写法。build90 为了先算
进料口径再发 stage 事件,改成了 `out = {...}` 再 `return out`,
于是那条断言读到空集合、报"键不齐"——**报的是写法变了,不是契约破了**。

改成看函数体里所有 dict 字面量,两种写法都认。
