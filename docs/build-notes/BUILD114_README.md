# 一、真正的病因

你那份 502 张卡片的扫描结果是这样的：

```
excess_mkt_21     502  100%      ← 三个窗口一起全空
excess_mkt_63     502  100%
excess_mkt_126    502  100%
excess_sector_*     1    0%      ← 板块超额完全正常
rs_mkt_samples    405            ← 对齐没问题
```

原因：**SPY 最后一根 K 线的收盘价是 NaN**（yfinance 尾行常见——当天那根
还没落定就先给一行空的）。你那张 MMM 卡片上的 reason 已经确认了：

```
excess_mkt_21 → 计算结果不是有限数（NaN/inf）—— 多半是面板里有缺失或异常的 K 线
```

## 为什么是这个形状

```python
def _ret(series, n):
    if len(series) < n + 1 or series[-n - 1] <= 0:   # ← 防了分母 ≤0
        return None                                   #   没防 NaN
    return series[-1] / series[-n - 1] - 1.0
```

**`NaN <= 0` 是 `False`**，所以一路放行、返回 NaN。
下游 `scrub()`（build111 加的）把 NaN 收成 null 加一句原因，
看起来像"处理过了"：**没崩、有解释，但全市场的大盘超额一起丢了。**

三个窗口同时空，是因为分子是同一个 `series[-1]`。
斜率那一支照算，是因为它的推导式里 `NaN > 0` 为 False、把那一根顺手滤掉了。

**这就是 build111「NaN 是第三种状态」那条教训，出现在一个 build111 没扫到的模块里。**

## 修三处

```
_ret()      两端都过 finite()，同时保留分母 ≤0 的老保护
align()     非有限的配对整对丢掉 —— 样本数从此说的是「能用几天」
null 原因   长度够、只是端点不可用时，不许再写成「样本不足 N 天」
```

最后这条单独说一句：**一个错的原因比没有原因更糟**，它会让下一个人
去查一个不存在的问题——我自己就是这么被带偏的（见下）。

# 二、我两次诊断错，第一次还照着错的假设写了防护

**第一次**：我说"SPY 面板取短了，对齐后只剩 20–63 天"。
**错的**。`rs_mkt_samples = 405`，对齐一点问题都没有。

我错在被 `rs_mkt_samples=405` 骗了——**那个数当时数的是"对齐了几天"，
不是"几天能用"**，NaN 也被数了进去。所以它不是一个诊断量，是一个安慰量。
现在 `align()` 过滤之后，它数的是可用天数（同一份数据会报 404）。

**更糟的是**：我按那个没验证的假设，先写了一个"基准取短了就告警"的防护。
那个告警在 405 行上根本不会响。**我防的是我猜的病，不是你得的病。**

那段防护留下了（取到 200 行而不是 400 行确实该报），
但**它不是这次的修复**，这次的修复是上面那三条。

# 三、顺带挖出来的第二个 bug：复核台账被当成了一个交易日

你跑诊断时掉出来的：

```
已存日期 ['2026-09-01', '2026-09-04', 'reviews']
```

`reviews.jsonl` 和卡片存在同一个目录，`store.dates()` 是
`glob("*.jsonl")` 取文件名。而 `events()` / `version_drift()` /
`hit_series()` 全都遍历 `dates()`——**台账的行一直在被当作信号卡片读。**

今天没出事，只因为台账的行里没有 `symbol` 字段、恰好被跳过。
**"恰好没出事"和"不会出事"是两回事。**

修两条，只修一条都不够：

```
台账搬出卡片目录     raw-data/technical_reviews/reviews.jsonl
                    （自动搬一次，旧文件改名为 .moved，不删除、不双写）
dates() 只认日期形状  ^\d{4}-\d{2}-\d{2}$，且**跳过了什么要写进日志**
```

第二条是因为"这个目录里只该有卡片"是一个约定，而**约定会被下一个人打破**——
备份、临时导出、`.DS_Store` 都可能落进来。

# 四、新增：全市场缺失扫描（这次真正缺的那一块）

**每个 null 都有原因**（build107）回答的是"这一格为什么空"。
它回答不了"这一整列为什么空"。**同一个正确的事实说 502 遍，
不会自己变成一个结论。**

`sweep.py` 每次快照之后跑一遍，判据**不靠拍阈值**：

```
成对不对称    excess_mkt_63 和 excess_sector_63 是同一段代码在两个基准上跑的
              一个全空、另一个基本满 → 差异只可能来自基准本身
              （这条和自己比，不需要任何阈值）

缺失率排行    只报数、不下结论。100% 缺和 2% 缺是同一句话的两个事实
```

拿你那天的形状喂进去，它会印：

```
全市场缺失扫描（502 张卡片）
  **成对基准不对称 —— 这不是个别票缺数据，是一路基准坏了：**
    excess_mkt_63 缺 100%　而同源的 excess_sector_63 只缺 0%　→ 差异只可能来自基准本身
  基准面板：yfinance:SPY(adjusted)　405 行（要 400 行）　2024-… … 2026-09-04
  **基准最后一根收盘是 NaN** —— 所有窗口的超额都共用这一根，
  会让全市场的大盘超额同时变 null（板块超额照常，所以很像个别票缺数据）
```

**扫描只数不修**——今天这份数据能不能用，是人的决定。

# 五、还有一处显示自相矛盾

你那两张卡片上写着：

```

    …
```

**100% 和三行之后的"缺"是同一张卡片自己打自己的脸。** 一族只要有一个成员

# 六、变异测试：32 个

```
家族层 + 覆盖度 12 个    第一轮 5 个漏网
扫描 + 显示      5 个    第一轮 1 个漏网
基准 NaN + 台账  15 个    第一轮 5 个漏网
```

漏网的原因**没有一个是断言写弱了**，全是同一类：

```
断言里写了 `if scored is not None:`        夹具没造出那种票 → 断言压根没执行
夹具每只票都是 4/5                         覆盖度不足那一支根本没走到
"一族都算不出来"                            在任何正常夹具下都是死代码
只在基准侧放 NaN                            个股侧的分支从来没被测过
断言"有一句提示"                            说错话的实现也有一句提示 ← 这条最隐蔽
```

最后那条值得单独记：`benchmark_last_note` 我原来只断"非空"，
而"最后一根坏"和"中间坏了几根"两种实现都会写一句话。
改成**断两种情况说的不是同一句话**才红——
**只要求"有输出"，等于只要求它没崩。**

补完之后**这一轮 32 个变异全被两个测试套抓到。**
