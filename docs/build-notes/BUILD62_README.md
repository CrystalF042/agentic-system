## 一、你收到的 PDF 是旧版式

首跑的 PDF 是"一部裁定 / 多头 / 空头 / 裁判综合 / 回测 / 材料"六节——旧结构。
**量化证据面板、反驳轮、论证审计、失效条件在交付物里全都不见了**，而且没有任何报错。

原因：`render_unit_a_md` 和 `render_unit_a_pdf` 是两个函数，我只改了前者。
**而 PDF 才是推给你的那份**，Markdown 只留在磁盘上。

这和 build59 那个"⁵ 渲染成空白"是同一类错误：改渲染必须两边一起改。
所以这次加了硬约束——自检逐项检查 PDF 里必须出现「量化证据面板」「论证审计」
「失效条件」「Round 2」「催化剂」，且不得再出现旧版式的「一部裁定」和「目标仓位」。

## 二、32 条 ⚠未核实 是我造成的

新提示词让模型用 `[面板]` 标注量化证据来源，但 `_verify_citations` 是旧世界写的，
只认数字编号 `[1]`..`[N]`。于是出现一个很坏的反向激励：

> **模型越听话地引用面板，被标 ⚠未核实 的就越多。**

首跑 32 条论据几乎全被标记，这个信号直接废掉——而面板恰恰是确定性生成、
最可溯源的那部分证据。

现在两类引用都算有效溯源，但性质分开：

| 标记 | 含义 |
| --- | --- |
| `[1]`..`[N]` | 指向采集到的原始材料，可点链接核对 |
| `[面板]` | 指向本轮确定性生成的量化证据面板，数字可复算 |

顺带修了：`【投资论点】`这类小节标题不再参与核验（它们不是论据）。
超范围编号（如 `[99]`）仍然会被标记。

修完之后同一份输入的未核实数应该从 32 降到个位数。**如果还是很高，那是真的有问题**——
说明模型在编造材料和面板里都没有的东西，那时候的 ⚠ 才是有意义的信号。
