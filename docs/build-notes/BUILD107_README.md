# 一、盘前那件事：我第一次的判断是错的

我先说了"它跑在 A 股模式下"。**不对。** 你发的 PDF 抬头写着

```
CIO Premarket Brief
2026-09-01 19:49 EDT ET
```

英文抬头、ET 时间戳、道指/标普/纳指/费半、美股期货、VIX、DXY——
**市场开关是对的，简报本身完全正确**，你说新闻也对。

错的只有一件事：**发车时间**。纽约 09-01 晚上 19:49，收盘四个小时之后。

## 真因

README 里那行：

```
0 7 * * 1-5   cd ... && .venv/bin/python run_premarket.py
```

那句写的是"**机器本地时间** 7 点"。你的 Mac 在北京时区。

```
北京 07:00  =  纽约前一天 19:00      （EDT，差 12 小时）
```

分毫不差。cron 成功、采集成功、PDF 成功、推送成功、日志全绿——
**没有任何一层问过"这份东西是给哪个市场的开盘用的"。**

## 为什么不能只改 cron 的小时数

把 `0 7` 改成 `0 19`，今天对，**十一月第一个周日之后错一小时**：
美国退出夏令时、北京不动，时差从 12 小时变 13 小时。一年两次，
每次错一小时，而且不会有任何提示。crontab 和 launchd 都只认机器本地时间，
跟不了另一个国家的夏令时。

## 改法：判断挪进 Python，cron 只负责敲门

新文件 `src/cio/schedule.py`。cron 每小时敲一次，**窗口外在发出任何网络请求之前
就退出**（用断网跑过，确实一个请求都没发）。

**你要做的就这一行：**

```
crontab -e
```

把原来那行换成：

```
0 * * * 1-5  cd ~/.openclaw/workspace/cio-agent && .venv/bin/python run_premarket.py
```

换时区、换机器、夏令时切换，以后都不用管。先看一眼它怎么说：

```
.venv/bin/python run_premarket.py --when
```

现在（你那台机器）会印：

```
现在不该跑：2026-09-01 20:06 EDT（US市场本地时间）不在盘前窗口 06:00–09:15 内，不发
下一班：2026-09-02 06:00 EDT（市场时区）

US盘前窗口（市场本地）：06:00–09:15
换算到这台机器现在的时区：       18:00–21:15
```

**夏天北京 18:00–21:15，冬天 19:00–22:15。** 这就是手抄进 crontab 会错的那一小时。

想立刻要一份，随时：`.venv/bin/python run_premarket.py --force`。
Telegram 里发"生成盘前简报"也照旧——**那条路径绕过时间闸**，
时间闸是给 cron 的排程规则，不是对你的拒绝。

## 顺手修掉抬头上那三条常驻降级

你那份 PDF 的 Data status 里挂着：

```
两市成交额取数失败；北向资金 已停披露(2024-08，不再计)；板块资金失败(ConnectionError)
```

三条都不是故障，是**在美股模式下去取 A 股口径的资金面**。akshare 那几个接口
本来就不认美股，于是每天必然失败三次，然后作为"降级"印在抬头上——
真正的降级（比如哪个新闻源死了）会被这三条常驻噪音淹掉。

us 模式现在如实返回空，并写明：**这是缺口，不是故障**（美股还没接免费资金面指标）。

文件名也改成按市场时区命名。原来文件名是北京时间 `202609020749`、
正文是 `09-01 19:49 EDT`——同一时刻、两个都对，但放在一起只会让人以为系统错乱。

## 还没改的（你可能会想要）

盘前用的 RSS 里还带着 cn 桶（财新、SCMP、东方财富、共同社）。
你那份美股简报的「Watch Today」里出现了"浙江宁波…"和几条 A 股外资流入，
共同社和财新还各失败一次。要不要在 us 模式下关掉 cn 桶，你说一声。

## 三件我想让你先知道的事

**一、日线看不见"资金流入"。** 你说的"有没有持续的资金持续流入"，
用 OHLCV 回答不了：我们有每天的总成交量和开高低收，**没有**谁在买、
单子多大、是不是同一个账户。OBV / CMF / 上下量比全都只是把成交量按当天涨跌
分个正负再累加——它们度量的是"上涨日的量和下跌日的量谁大"。
所以那组指标叫 `accumulation_pressure_proxy`，**proxy 这三个字母是它最重要的部分**，
而且它不是一个分数，是四个并列的数（v1 不打分）。

**二、"四个峰值都在这里高度"是这样算的**：pivot 窗口 5 → 按 0.5×ATR20 聚类 →
触碰间隔≥5 去重 → 至少 2 次才成区。参数和版本号绑死了，
改参数不改版本号测试会红。为什么冻结：四个参数各试三种就是 81 套，
在同一份历史上挑"看起来最准"的那套，挑出来的是历史噪音的形状——
证券二部已经吃过一次这个亏。

**三、最后 5 根 K 线上的高点，今天还不算 pivot。** 它要右边也有 5 根才能确认。
不管这件事，"截止今天的价区"里就含着未来 5 天才知道的信息，图上完全看不出来，
回测一路变绿，实盘那 5 天你根本没有那条线。代价是最近 5 根不参与——**这是诚实的代价。**

## 变异测试抓到了我四条不合格的用例

写完 25 条测试之后，我照例把每条规则故意改坏，看测试红不红。**四条没红**：

```
把 pivot 改成不要求右侧确认（一个货真价实的未来函数）    25 条全绿
把相对强度改成按行数对齐（不按日期）                    全绿
把 rvol 分母改成含今天                                  全绿
```

三条的原因都不在断言，**在喂给断言的数据**：

- 回放测试用的是单调上涨的直线，而**单调序列里一个 swing 点都没有**，
  价区两边都是空，永远相等。换成带摆动的行情，立刻红。
- 对齐测试只断言"样本数变少"——60 行和 57 行按位置截齐也是 57 行。
  改成断言**配对的值**（基准多三个更早的日子时，按位置配会整体错三天），立刻红。
- rvol 测试用的是 30 天等量 + 今天 3 倍，而**中位数对单根异常本来就不敏感**，
  含不含今天是同一个中位数。换成一半 1M 一半 2M（含今天会把中位数从 1.5M 挤到 2.0M），立刻红。

第四条是等价变异：删掉 `observe` 里对基准的截断，结果完全不变——
因为 `align()` 按日期取交集，个股已经截断了，交集自然不含未来。
那两行留着是第二道，**第一道是日期对齐**，我把这件事写进注释了。

## 下一步该看的

```
.venv/bin/python scripts/technical_distribution.py --limit 120
```

打印全市场分位和**基础率**：今天有百分之多少的票量比≥1.5、多少只在一年区间的 95% 以上、
多少只距上方价区 0.5 个 ATR 以内。

**在知道这些数之前不要做提醒逻辑。** "成交量连续加大"听起来稀有，
但如果全市场每天有 12% 的票满足，那条提醒每天会给你六十条。
先把基础率印出来，再决定阈值——顺序反过来就是证券二部那次的复现。
